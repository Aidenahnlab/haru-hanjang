## Vercel 배포 (GitHub 연결)

1. 로컬에서 `npm run build`가 통과하는지 먼저 확인
2. Vercel 로그인 → **직접:** 계정 만들기·로그인
3. **직접:** GitHub에 **Vercel GitHub 앱 설치** (github.com/apps/vercel). Vercel이 저장소를 읽고 push 알림을 받으려면 필요. 설치 전에는 Deploy를 누르면 "install the GitHub integration first"가 뜬다
4. `vercel.com/new/import?s=<저장소 주소>`로 가져오기 → Application Preset이 **Vite**로 잡혔는지 확인 → 환경 변수 없음 → Deploy
5. 끝나면 **Settings → Domains**에서 실제 주소를 확인

## 다음에 참고할 교훈

- **배포할 브랜치에 앱 코드가 있는지 먼저 본다.** 이번엔 작업이 모두 `docs/product-brainstorm` 브랜치에 있고 `main`에는 docs만 있어서, Vercel이 프레임워크를 "Other"로 잡았다. `main`을 작업 브랜치로 fast-forward해서 push한 뒤에 Vite로 인식됐다. 다음에는 작업 묶음이 끝날 때마다 `main`에 합쳐 두면 이 단계가 필요 없다.
- **배포 주소는 짐작하지 말고 Vercel에서 읽는다.** `프로젝트이름.vercel.app`은 모든 사용자가 같이 쓰는 이름이라 이미 남이 쓰고 있을 수 있다. 이번에도 `haru-hanjang.vercel.app`은 남의 서비스였고, 우리 주소는 `-mu`가 붙었다. 열린 화면이 우리 앱인지(제목·첫 화면)도 코드와 맞춰 본다.
- **흉내 낼 것을 주소 뒤 옵션으로 만들어 둔 게 점검을 빠르게 했다.** `?now=…`로 다음 날 아침·자정 직전을, `?save=fail`로 저장 실패를 기다리지 않고 확인했다. 배포된 주소에서도 그대로 쓸 수 있다.
- **아직 실제 폰에서 못 본 것:** 길게 눌러 고치기, 다른 앱에 갔다 돌아왔을 때 새 장 펼치기 ([work/LOG.md](work/LOG.md)의 "다음에 할 것").
